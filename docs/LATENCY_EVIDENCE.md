# Latency evidence classification

| ID | Mechanism | Class | Can support sub-ms claim? |
|----|-----------|-------|---------------------------|
| L1 | `sim.metrics.inference_latency_ms` around a no-op / tiny Python function | `HOST_PROCESS_TIMING` | **No** |
| L2 | `time.time()` inside exhaustive / hierarchical search | `HOST_PROCESS_TIMING` | **No** (codebook search on CPU, synthetic `H`) |
| L3 | LSTM `forward` if torch is installed | `HOST_PROCESS_TIMING` | **No** unless a named DUT, frozen engine, and protocol are added |
| L4 | README historical 0.8 ms LSTM | **unsourced** | **No** — see [legacy table](uml/legacy/unsourced_benchmark_table.md) |
| L5 | ONNX / TensorRT / gNB | not implemented | **No** |

**Rule:** sub-millisecond inference remains **unproven** until L3/L5-class evidence exists with clock source, batch size, device name, and commit SHA.

Harness output: `results/timing_harness.json` (generated by `make timing`).
